# Security

TannX OS is a hobby operating system for a lab. It is not hardened, it
has no security boundary against a hostile network, and it does not
pretend to. This page states the model so that nobody is surprised.

## The trust model

1. **Trusted LAN.** TannX OS assumes every machine on its network segment
   is friendly. Its UDP telemetry (port 4711), the proxy discovery
   broadcast (port 4080) and the LLM/HTTP traffic are plain text with no
   authentication and no encryption. There is no TLS in the OS and none
   is planned.
2. **Trusted ring 3.** Userspace programs run in ring 3 with fault
   isolation, but two syscalls - `sys_pci` (16) and `sys_mmio_map`
   (17) - let a ring-3 program configure any PCI device and map its
   MMIO, which means DMA. This is deliberate: it is what allows the NVMe,
   xHCI, virtio and HDA drivers to be written in C and live in ring 3.
   The MMU still protects the kernel (page 0 unmapped, #PF/#GP isolation,
   `sc_chkbuf` on every pointer argument, `sys_mmio_map` refuses any page
   inside mapped system RAM), but a ring-3 program with a DMA engine can
   defeat that. Do not run code you do not trust in ring 3.

## Remote control is a build option, off by default

The default build has **no remote control**. The UDP control channel on
port 4713 (EXEC, REBOOT, ABORT, MISSION, STATUS, RESULTS, DMESG, RUNPROG,
SELFTEST) and the USB keyboard diagnostic broadcast are compiled in only
with

```
make REMOTE_CTL=1
```

That build accepts shell commands and reboots from anyone who can send a
UDP packet to the box. It exists for the lab loop (deploy over PXE, drive
hardware tests, read the kernel log of a headless machine) and must only
run on an isolated, trusted LAN. The host-side scripts for it live in
`tools/lan/`.

## The LLM proxy

`llm-proxy.py` turns the OS's plain-HTTP requests into calls to an LLM.
It has no authentication:

- It binds to `127.0.0.1` by default; `--bind 0.0.0.0` exposes it to the
  LAN and is meant for a trusted lab network only.
- The default backend is the vendor API (`ANTHROPIC_API_KEY`). `--mock`
  answers with canned text for the tests. OpenAI-compatible endpoints
  and Ollama are selected per request with `@openai` / `@ollama` and
  configured through environment variables.
- The Claude Code CLI backend is available only when started explicitly
  with `--backend claude`, and it is run without tool permissions. Keep
  it that way: a proxy that forwards arbitrary LAN input to a tool-using
  agent on the host is a remote code execution path.
- The proxy keeps the autopilot's program library in a JSONL file on the
  host. Treat it as untrusted content generated by a model.
- `/fetch` (the `run www` browser, `proxy_ext.py`) makes the proxy fetch
  web pages for the OS. It is **SSRF-guarded**: http(s) only, no userinfo,
  and every address the host name resolves to - and every redirect target
  - must be a global address (loopback, RFC1918, link-local/CGNAT,
  multicast and `.local` names are refused), so a page request from the
  OS cannot be turned into a probe of the proxy host's LAN or a cloud
  metadata endpoint. Pages are size-capped (512 KB read, 24 KB of text).
  The resolve-then-connect check is not rebinding-proof; the guard is a
  seatbelt for a LAN tool, not a hardened egress proxy.
- `/cast/*` (`run cast`) drives Chromecasts the proxy host **discovered
  itself** by mDNS (pychromecast or the catt CLI); the OS names a device
  and a media URL, it cannot point the proxy at an arbitrary host. The
  media URL is fetched by the Chromecast, not by the proxy.
- `/shot` accepts a BMP (max 8 MB) and writes it under `AGENTOS_SHOT_DIR`
  (default `./shots`) with a timestamp name it chooses.
- All of this is reachable by anyone who can reach the proxy port, which
  is why the default bind stays `127.0.0.1`.

## What the LLM loop means for your host

`llm`, `llmscript` and `autopilot` send text typed in the OS (or chosen
by the autopilot) to a model and execute what comes back *inside the
OS*. Scripts can only use the OS's own shell commands; they cannot touch
the host. The host-side risk is limited to the proxy process and its
backend credentials. Do not give the proxy a backend that can act on the
host.

## Disk safety

The OS's ATA/AHCI drivers can write the first internal disk of a real
machine. `diskon` arms writes only when it finds the `AGENTOS-MEDIUM`
marker; otherwise writes go to RAM and the disk is untouched.
`ahcibless` and `awrite` are explicit, destructive and documented as
such. `usb backup` refuses to overwrite a stick that carries a FAT, MBR
or GPT signature unless forced. See `docs/BARE-METAL.md`.

## Reporting

If you find a bug that breaks the stated model - a ring-3 program that
can write kernel memory without DMA, a network parser that overflows, a
way to defeat the medium marker - please report it rather than posting
an exploit. Security contact: see the repository owner's profile.
Include the version string from the boot banner and, if possible, a
QEMU reproduction (the gate scripts in `test*.sh` show how to drive the
OS headlessly).

There is no bug bounty. Fixes land in the next commit after they pass
`make test-all`.
