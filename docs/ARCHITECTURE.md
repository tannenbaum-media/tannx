# TannX OS architecture

The reference for anyone (human or LLM) changing the kernel or the
userland. Everything here is derived from the code; when the two
disagree, the code wins and this file gets fixed.

Contents: orientation map, boot paths, memory map, data structures and
the syscall ABI, the iron rules, classic pitfalls, the trust model, and
lessons learned the hard way.

Two kinds of code live in the kernel image: ring-0 kernel code and the
agent workers (`am_math` and friends), which are linked into the same
image but execute in ring 3 (CPL 3), read `tasks_tbl` read-only and
report through syscalls. Adding an agent type touches `parse_type`, the
worker dispatch, `type_names` and the spawn/task parsers.

## 2. Boot paths

All paths end in the same 32-bit kernel at physical 0x7E00.

- **BIOS**: Stage 1 in the boot sector loads 256 kernel sectors with two
  128-sector INT 13h/42h DAP reads (SeaBIOS EDD refuses more than 128
  sectors per call), or via CHS when the boot drive is a floppy (DL <
  0x80). Stage 2 sets video mode 3 (the last BIOS call), collects the
  E820 map, enables A20, loads the GDT and jumps to protected mode.
- **UEFI**: `BOOTX64.EFI` (agentos-uefi.S) runs in long mode, reads
  `kernel32.bin` from the ESP, enumerates GOP modes, calls
  ExitBootServices, then descends to protected mode with its own GDT and
  jumps to `uefi_entry32`. It leaves a boot-info block at 0x28000 (magic
  "UEFI", framebuffer base, resolution, pixels per scanline, mode list).
  The kernel renders the 80x25 console into the GOP framebuffer with its
  own 8x16 font.
- **Hybrid image**: sector 0 is both a BIOS boot sector and an MBR with
  one type-EF partition (ESP at LBA 2048). BIOS runs the code, UEFI
  firmware reads the partition table. One stick boots both worlds. The
  Stage 2 UEFI handoff pointers live at Stage 2 offsets +516/+520, out
  of the partition table's way.
- **PXE**: `pxe.img` = `pxe_stage1.S` + the flat kernel. The NIC option
  ROM downloads the file to 0x7C00; the kernel lands at 0x7E00 exactly
  where the disk Stage 1 would have put it, and the stub falls through.
  No disk is needed; AgentFS slots become RAM-backed (see diskon).

## 3. Memory map (physical = virtual, identity-mapped 0-32 MB)

```
0x00000-0x00FFF  page 0: UNMAPPED (NULL protection). IVT/BDA are dead after boot.
0x04000          E820 usable-RAM total (real mode INT 15h E820 -> PM; 0 = CMOS fallback)
0x07C00-0x07DFF  Stage 1 (boot sector + MBR partition table at offset 446)
0x07E00-0x27DFF  kernel (budget end 0x27E00 = 256 sectors) - ring-3 view: readable, W=0
0x28000          UEFI boot info (magic "UEFI", +8 FB base, +16 vres<<32|hres,
                 +24 PixelsPerScanLine, +0x1c GOP mode count, +0x20 mode list)
0x29000-0x2AFFF  AHCI: CLB 0x29000, received FIS 0x29400, command table 0x29800,
                 sector buffer 0x2A000 (the controller DMAs to these addresses)
0x2F000-0x2F7FF  IDT (256 gates, built at runtime)
0x30000-0x30FFF  page directory
0x31000-0x38FFF  8 page tables
0x39000          RTL8139 RX ring (8K+16+slack), physical DMA target
0x41000-0x48FFF  kernel stacks of the agent threads, TID 1-8, 4 KB each
0x49000          RTL8139 TX buffer   0x49F00 netwish payload   0x4A000 frame build
0x50000-0x8FFFF  kernel heap (kmalloc/kfree, supervisor-only; relocates to 64 MB
                 on machines with >= 96 MB RAM)
0x9F000          shell stack (grows down)
0xB8000          VGA text RAM (supervisor-only: 'task scan b8000' kills the agent)
0x100000-0x102FFF RTL8168 RX buffers (0x100000) + dmesg ring (0x102000)
0x103000         PEND_BUF (shell ';' chaining)      0x104000 AC97 BDL
0x105000-0x133DFF AC97 PCM tone buffer (1 s, 48 kHz, 16-bit stereo)
0x134000-0x134AFF SCRATCH: tss (8x104) 0x134000, cursor_save_buf 0x134400,
                 fs_buf 0x134800, inbox_buf 0x134A00 - zeroed at boot
0x136000         SLOT_RAM: RAM-backed AgentFS slots (17 x 512 B) when no medium marker
0x13B000-0x13C7FF e1000 TX ring (0x13B000) + TX buffer (0x13C000)
0x141000+        user stacks of the agent threads, TID n at +n*0x1000 [U=1,W=1]
0x150000         virtio-net RX/TX virtqueues (free bank 0x149000-0x300000)
0x400000         ring-3 C program (user.bin, loaded by 'run'); 0x7FF000 = USER_ARG
Disk LBA 256     medium marker "AGENTOS-MEDIUM": without it diskon arms RAM-backed
                 slots instead of the disk, so a foreign disk is NEVER written
Disk LBA 257-264 AgentFS (8 slots x 512 B; ring 3 writes them only via SYS_WRITE_SLOT)
Disk LBA 265-272 wish slots (magic "AW")   LBA 273 persisted tasks_tbl (magic "AT")
Disk LBA 300-683 user.bin (ring-3 blob, up to 192 KB = USER_BLOB_SECTORS)   LBA 1024 video.mjpg
Disk LBA 2048    ESP (FAT12) of the hybrid/UEFI image
```

Hardcoded addresses are named `.equ` constants in the kernel; the table
above is the human-readable copy. A layout move must also be grepped in
the host scripts (Makefile, wishes.sh, tests): the v1.78 move from LBA
100 to LBA 257 left three host-side readers on the old numbers for ~70
versions without any QEMU suite noticing.

## 4. Data structures and ABI

- `agents_tbl`: 8 x 8 bytes. +0 used, +1 type (0 math / 1 scan / 2 count /
  3 prime / 5 ask / 6 gcd / 7 fault), +2 status (0 idle / 1 busy), +3 task
  index (0xFF = none), +4 done (word), +6 progress.
- `tasks_tbl`: 8 x 16 bytes. +0 used, +1 type, +2 status (0 waiting /
  1 running / 2 done / 3 ERROR), +3 agent, +4 a (word), +6 b (word), +8 op,
  +12 result (long). `scan` stores its address as a long at +4
  (overlapping b); `gcd` uses +4/+6 as two 16-bit inputs. The hidden type
  `fault` executes `ud2` in ring 3 so the gate can prove #UD isolation.
- **Heap**: arena 0x50000-0x8FFFF, first-fit free list, 16-byte header
  (+0 magic 0xA110C8ED, +4 size, +8 next, +12 free flag). `kmalloc`
  (EAX = size -> EAX = pointer or 0, rounds to 16, splits remainders >= 32);
  `kfree` (EAX = pointer -> 0 ok / 1 no block / 2 double free; range
  check BEFORE the magic read, otherwise `free 123` faults in page 0).
- **Threads**: `cur_thread`, `tcb_state[9]` (1 = runnable; thread 0 is
  the shell and always runnable), `tcb_esp[9]`. TID = agent slot + 1. The
  timer ISR saves ESP, `thread_resume` sets TSS.ESP0 for ring-3 threads,
  loads the target ring's data segments (real CPUs NULL DPL-0 selectors
  on a return to ring 3; QEMU does not) and switches.
- **SMP**: the boot path is single-core. `smpon` wakes the application
  processors (INIT-SIPI-SIPI); each core has its own TSS/ESP0/cur_thread
  and runs the same round-robin scheduler. `sched_lock` and `tbl_lock`
  (xchg spinlocks, only ever held with interrupts off) serialize the
  run queue and the claim/finish table mutations across cores.
- **Agents never write tables or the screen**: syscalls only. Reading
  ticks and their own task fields is allowed. hlt/cli/in/out from ring 3
  are a #GP and cost the agent its life.
- `putc` is atomic (pushfl/cli ... popfl) and mirrors every character to
  COM1; the status line is deliberately not mirrored. ISRs do only
  pushal/popal + cld, never touch segment registers, EOI to port 0x20.

### Syscalls: INT 0x30, the only DPL-3 gate

EAX = number, EBX (and ECX) = arguments, return value through the saved
EAX slot (`28(%esp)` in the pushal frame). Every pointer argument is
validated by `sc_chkbuf` against the ring-3 window. The gate is an
interrupt gate (IF=0 inside), and the ISR executes `cld` first because an
interrupt gate does not clear DF.

```
 0 yield          1 claim           2 progress (+ watchdog heartbeat)
 3 finish         4 exit            5 write (buf,len)      6 putc
 7 fbinfo         8 getkey          9 uptime              10 read_sectors
11 sbrk          12 net_tx         13 net_rx              14 net_mac
15 write_slot    16 pci_cfg        17 mmio_map            18 task_info
19 console       20 agents         21 atp                 22 setmission
23 sysinfo       24 kbgrab         25 fgrab               26 shell
```

Notable doors: 15 WRITE_SLOT writes AgentFS slots only and is diskon-gated
(this is how llmscript persists LLM-written scripts); 16 PCI_CFG and 17
MMIO_MAP (an uncached user 4 MB page, rejected for anything inside mapped
system RAM) exist so that drivers can live in ring-3 C; 19 CONSOLE copies
the cursor and the 80x25 text mirror (0xB8000 is write-only graphics RAM
under VBE/GOP); 20 AGENTS copies agents_tbl + tasks_tbl (192 bytes) for
the desktop's agent panel; 21/22 read and set the autopilot mission
telemetry (48-byte slot); 23 SYSINFO copies the read-only facts a ring-3
system card needs (E820 RAM, cpu_mhz, cpu_count, the console attribute,
boot path, NIC id, diskon, kernel bytes, ticks, version string - 64 bytes).
5 WRITE honours the console's `0x01 <attr>` colour escape like `puts_attr`,
so `fetch` can paint; a program restores the attribute it got from SYSINFO.
24 KBGRAB makes the caller the foreground program (`fg_prog`, what the
`snake` launcher does for a game) so typed keys go only to the ring-3 key
ring and not to the shell's line editor, and takes the framebuffer the same
way the compositor does (`compositor_active`, so the kernel stops mirroring
console text and the status line into it). The borrowing thread is recorded
in `fb_owner` (shared with the `forest` launcher); exit, kill and a fault
release keyboard and gate only when that thread goes away (`fx_release`). The user-space stubs are in
`user/libc.h`.

25 FGRAB(1) is the same grab as 24 KBGRAB (one mechanism, one owner in
`fb_owner`) for the `run <app>` programs that toggle it (tour, www, files,
cast, rain); FGRAB(0) gives keyboard and gate back early through the same
`fx_release` (owner only) and repaints. 26 SHELL(buf,len<=60) types a line
plus Enter into the shell's keyboard buffer - the tour runs `spawn prime`
for real this way and reads the result back through 19 CONSOLE.

**Key ring codes** (SYS_GETKEY): printable ASCII as typed; with a
foreground program also the control codes (Ctrl+S = 0x13, Tab, Ctrl+C) and
the navigation keys as `0x80 | PS/2 scancode` - 0xC8 up, 0xD0 down, 0xCB
left, 0xCD right, 0xC7 Home, 0xCF End, 0xC9 PgUp, 0xD1 PgDn, 0xD3 Delete.
The serial decoder maps the vt100/xterm sequences (`ESC [ A`.., `ESC [ 1~`..)
onto the same codes and delivers a lone Escape as `ESC ESC`, so a program
behaves the same on the PS/2 keyboard and over the serial console the gate
drives. `user/ui.h` names them.

### The script engine

`script <slot>` feeds a 512-byte AgentFS slot through the shell's `;`
chaining machinery: every shell command is a statement. `sleep`, `if`
(task results or the two registers), `repeat`, `set`/`setb` (registers A
and B, substituted as `$` and `#`), `waittask`, `waitall` and `wait` make
it a small language. `llmscript <slot> <task>` lets the LLM write such a
script through the proxy's `/script` endpoint; `autopilot` chains
`llmscript 7 ...; wait; script 7` forever. The register substitution runs
at the dispatcher with `fs_buf` as scratch and a 254-byte line cap.

### Audio: the ring-3 HDA engine (user/audio.c)

One controller bring-up (SYS_PCI + SYS_MMIO_MAP, immediate command
interface, no CORB/RIRB) and a codec walk that finds BOTH paths: DAC +
output-capable pin, ADC + input-capable pin (the pin's default-config
device prefers Mic over Line-in; the ADC's connection select is pointed at
that pin, its input amp unmuted at the 0 dB offset of its amp caps). Two
cyclic rings, 48 kHz 16-bit stereo, AU_NCHUNK = 32 BDL entries of
AU_CHUNK = 512 frames (10.7 ms): the output descriptor is the first one
after GCAP.ISS input descriptors (stream 1), capture uses input descriptor
0 (stream 2). No interrupts: apps poll LPIB. `au_out_next()` hands out the
chunk AU_LEAD entries ahead of the DMA read position, `au_in_next()` the
oldest chunk the DMA engine has finished writing.

Paid-for lessons:

- **AU_LEAD must outlast a scheduler slice.** Round-robin runs the shell's
  idle loop for a whole 55 ms tick while the app is descheduled; a 32 ms
  lead underran on every tick. 8 chunks (85 ms) is the floor; the apps do
  not `sys_yield` in their loops for the same reason (a yield parks them
  for up to two ticks).
- **Draw the framebuffer row by row.** A 1-px vertical strip per waveform
  column made every store a cache miss 10 KB apart: ~500 ms per frame at
  2560x1600 under TCG and the capture ring lapped. Row-contiguous stores
  run at ~70 M px/s; the same frame costs ~25 ms.
- **The key ring holds the command line.** SYS_GETKEY delivers every byte
  typed since boot, including `run rec test` itself ('r' started a take,
  's' saved it). Every foreground app drains the ring before its loop.
- **Console output under a framebuffer app scrolls the framebuffer.** The
  kernel renders console text (and `fb_scroll`s the client area) while a
  ring-3 program owns the screen. The apps print their banner before
  `ui_begin()` and their results after the UI, test modes excepted.
- QEMU's `-audiodev none` runs both DMA engines at the nominal rate and
  captures silence; there is no file-backed capture backend in QEMU 8.2
  (`wav` is playback-only and not built on Debian). The test modes
  therefore inject `au_test_pattern()` behind the DMA, so LPIB progress
  (real DMA) and non-silent samples (real processing) are both asserted,
  and REC.WAV is read back from the virtio-blk image with mtools.
- `voice` POSTs a 16 kHz mono WAV (64 KB per 2 s) through `http_xfer`'s
  binary-body path: MSS-sized segments in bursts of 8, then a short ACK
  drain - slirp delays lone ACKs ~200 ms, so per-segment waits would take
  20 s. The transcript is staged as the script `wish <text>` in slot 7
  (SYS_WRITE_SLOT, diskon-gated); `script 7` then goes through the real
  `wish` command. The proxy's `/stt` runs faster_whisper/whisper or
  forwards to `STT_URL`; `--mock` answers a fixed transcript.
- The kernel keeps two hooks only: `beep` launches `run beep` when
  `pci_find_class` sees class 04:03, and a `make CHIME=1` kernel
  (`.ifdef BOOT_CHIME`, zero bytes otherwise) runs `chime` at boot.

### Protocol constants (keep the old name on purpose)

The project is called TannX OS; it was AgentOS. Every user-visible
string says TannX, but the tokens other programs match byte for byte
keep the old spelling - renaming them would break existing media, host
tools and lab scripts:

- `AGENTOS-MEDIUM` - the on-disk marker at LBA 256 (`diskon`, `run`,
  `ahcibless`, the Makefile image targets).
- `AGENTOS-*` wire tokens - `AGENTOS-PROXY?` / `AGENTOS-PROXY` (proxy
  discovery), `AGENTOS-WISH` / `-WISH-ACK` / `-WISHES`, `AGENTOS-ABORT`,
  `AGENTOS-REBOOT`, `AGENTOS-OUT` / `AGENTOS-END` (remote EXEC framing),
  `AGENTOS-LLM-MOCK` (the mock proxy's answer prefix the suites grep).
- `AgentOS/32 v<ver> ` - the prefix of every UDP report (STAT, RSLT, DONE,
  DMSG, the boot log line); `tools/lan/*` and `test-remote` match on it.
  SYS_SYSINFO hands the same string to ring 3 (`fetch` cuts the version
  out of it).

## 5. Iron rules

1. `make test-all` green before every commit. No exceptions.
2. **Protected strings** (test.sh greps them; change only together with
   test.sh): the banner word `TannX`, the prompt `tannx> `,
   `msg_spawn3` (") agent ready..."), `msg_res` (" = "), `msg_load2`
   ("]: "), the status names waiting/running/done/ERROR, the result
   format of print_tasks, and the #PF/heap messages.
3. ASCII only in OS strings; code, comments and docs in English.
4. **Size budget**: kernel content < 131072 bytes (`.org 131072` fails
   otherwise). Check the real content with the `KSENT256` sentinel in the
   last sector, not just msg_halt. Raising the budget is not a one-line
   bump: Stage 1 loads exactly 256 sectors in two DAP reads, the kernel
   tail at 0x27E00 butts against UEFI_INFO at 0x28000, the LBA 256 marker
   and slots cap the disk region, and `pg_img` must cover the kernel
   pages. Growing past 256 sectors means relocating the 0x28000 /
   USER_STACKS / NIC-ring structures.
5. Page 0 is off-limits (NULL protection). **Never set CR0.WP**: the
   kernel writes U=1/W=0 pages only because WP=0; `paging_init` forces
   WP=0 because UEFI firmware hands over with WP=1 (#PF recursion, triple
   fault - paid for). There is exactly ONE DPL-3 gate (0x30).
6. One change = one commit.

## 6. Classic pitfalls (each paid for at least once)

- PIC remap is mandatory (IRQ0-7 collide with exceptions otherwise).
- After the protected-mode jump: never a BIOS interrupt again.
- Timeout loops need an explicit `mov $0x10000,%ecx`; `xor %ecx,%ecx` +
  `loop` is 4 billion rounds in 32-bit mode.
- `rep insw/outsw` need the 66 prefix (gas emits it; check the disasm).
- Pointer tables are `.long` with `(,%reg,4)` indexing.
- New threads: set `tcb_state` LAST, after the frame is complete.
- A synthetic frame needs EFLAGS 0x202 (IF set) or the thread runs with
  interrupts off forever.
- #PF/#GP handlers never clean up the CPU's error code; both paths
  replace ESP completely.
- VMware mounts .img files as floppies: Stage 1 keeps the CHS path.
- Real CPUs NULL DS/ES/FS/GS holding DPL-0 selectors on an iret to ring 3;
  QEMU does not. Load the target ring's data segments before the iret.
- **RTL8168 RX wedges after one ring pass unless net_poll acknowledges
  the ISR (write-1-to-clear) every tick.** Do not "recover" by rebuilding
  the descriptor ring in the poll: that sets OWN=1 over a frame the NIC
  just DMA'd and eats it. Diagnosed blind via the `nicdbg` register dump
  over UDP, because QEMU has no RTL8168 model.
- Polled device drivers: busy-poll first (~200k iterations), yield only
  if still pending. Yielding a whole timer tick per request made a
  multi-cluster FAT write take 15 s instead of 1 s.
- FAT writes: scan free clusters up to the REAL cluster count computed
  from the VBR, never up to the FAT-entry count, or you allocate past the
  end of the disk. Read each FAT sector once (RAM scan).
- `test.sh` has a per-run watchdog (`TO`). Every feed step lengthens the
  run; when QEMU gets killed mid-feed the symptom is a "broken pipe"
  (exit 141), not a real failure. Bump `TO` or trim the feed.
- The UEFI loader is the most fragile file in the repo: MS x64 calling
  convention (RCX/RDX/R8/R9, 32-byte shadow space, RSP 16-aligned at
  calls), and OVMF (`make test-uefi`) is the only automated test.
  Nothing may be written to firmware-owned pages before ExitBootServices.
- A foreground ring-3 program and the compositor share one `user.bin`
  and one `.bss`: crt0 zeroes it on start, so a preempted compositor
  must snapshot its pointers and null-guard them.
- `smpon` is opt-in since v2.74: a faulting application processor
  boot-loops real hardware, so the kernel never wakes APs on its own.

## 7. Trust model (decided, documented, not a bug)

TannX OS is a lab OS. It assumes a **trusted LAN** and treats its **ring-3
userspace as trusted**. Consequences:

- The remote-control channel on UDP port 4713 (EXEC, REBOOT, ABORT,
  MISSION, STATUS, RESULTS, DMESG, RUNPROG, SELFTEST) is unauthenticated.
  It is therefore **compiled out of the default build** and only present
  with `make REMOTE_CTL=1`, together with the USB keyboard diagnostic
  broadcast. The EXEC copy is length-bounded; the issue is the absence of
  authentication, not memory safety.
- `sys_pci` (16) and `sys_mmio_map` (17) let a ring-3 program drive any
  PCI device, including DMA. This is what allows drivers to live in
  ring-3 C. The MMU still protects the kernel: NULL guard, fault
  isolation, `sc_chkbuf` on every pointer syscall, and `sys_mmio_map`
  rejects any page inside mapped system RAM so ring 3 cannot alias the
  kernel heap (`run mmcheck` proves the refusal).
- The host-side LLM proxy speaks plain HTTP without authentication; it
  binds 127.0.0.1 by default.

Untrusted code does not belong in ring 3 here, and the box does not
belong on an untrusted network. Details and reporting: `SECURITY.md`.

## 8. Lessons learned

- "Works in QEMU" is not "works on silicon", and the gap is widest at
  privilege transitions, DMA and firmware handover. Mark anything not
  run on hardware as untested.
- A protective refusal that blocks the headline feature is a design
  smell. Find the path that keeps the protection AND unblocks the feature
  (diskon on a diskless box: do not refuse, redirect the slots to RAM and
  never touch the foreign disk).
- A driver that reports its own registers over the wire can be brought
  up on hardware you cannot see (AHCI, RTL8168).
- A routine called from the idle loop interrupts arbitrary shell code and
  must preserve every register (the USB keyboard EDI clobber).
- For storage, prove that the bytes land in the host backing file and
  round-trip through host tools (mtools, curl). For graphics, compare
  screendumps. For sound, assert DMA progress (CIV/PICB, LPIB) because the
  gate cannot hear.
- The QEMU test is the truth; disassembly checks (`objdump -b binary
  -m i386`) remain useful for frame and gate bytes.

## 9. Debugging

`make debug32` starts QEMU halted with a GDB stub on :1234. In a second
terminal: `gdb agentos32.elf -ex 'set architecture i386' -ex 'target
remote :1234'`, then `b pf_handler`, `c`, and trigger `task scan b8000`
in the VM. `p/x $cr2` works directly; `x/1bx &cur_thread` names the
culprit. The stub patches no guest RAM, so breakpoints survive the kernel
load by Stage 1. `dmesg` in the shell shows the kernel event log; with
REMOTE_CTL the same log can be pulled over UDP.
